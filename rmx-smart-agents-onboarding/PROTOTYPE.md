# Smart Agents: Onboarding Workflow

The Smart Agents workflow builder, showing the **Prospect Onboarding** agent: a trigger ("When a lease is signed") feeding an Onboarding checklist, conditional branches (pet, vehicle, move-in coordination) with additional Onboarding steps, and a closing trigger and Notify step.

## What works

- Zoom (25–200%) with −/+, Fit, trackpad pinch, or Ctrl/Cmd + scroll; it zooms about the cursor. Plain scroll pans the canvas.
- Drag a step card to reorder it within its Onboarding node or move it into another one (a blue line shows where it will land). Dropping onto a collapsed node adds it to the bottom.
- The canvas is a flowing layout, and the dashed connectors are redrawn from the real node positions. Collapsing an Onboarding node (its chevron) pulls everything below it up.
- Click an Onboarding node to select it (inspector: Settings and Connections). Click a **step** inside it to select the step (blue border, Figma "Step edit") and the inspector shows that step's settings, the same ones the Onboarding Template designer offers for that step type:
  - every step: Step Name * (also renames the card and the inspector title), Required
  - Renters Insurance: "Allow prospects to self-enroll in master policy" (wording from the Figma Step edit frame; the template says "Self-enroll in master policy")
  - Payment Setup and Make a Payment: the template's info text, as a plain section above Settings
  - Form: Select Form (Pet Addendum, Pet Information, Gym Access, Notice to Vacate, plus the step's own form); the card's second line follows the choice
  - File Upload: **File Request**, one file per File Upload step (File Name *, Help Text, Required, Allow multiple uploads); there is no Add File, so a second file means a second File Upload step
- The right panel only shows while something is selected (an RMR node or step, a Trigger, a Condition or a Notify node); click empty canvas to deselect and the panel hides, giving the canvas the full width.
- **RMR steps** (called Onboarding before the 13 Nov mock). The left panel only holds the step library (Trigger, RMR, Action, Condition, Notify, Assign To, Wait). An RMR node's inspector has Settings (Step Type, which is **Onboarding** or **Form**, and the name, which renames the node). Changing the type renames a step that still has its original name (to "Form", and back to its original name if you switch back); a name you have typed yourself is never changed. With type **Form** the RMR step is a single form with the same settings as the Form step in the Onboarding Template (Step Name *, Select Form, Required): the canvas shows one form card (with the chosen form) in place of the list of steps, the Onboarding Steps list is hidden (the steps are kept and come back if you switch to Onboarding), and grouping, connections and undo work as for any RMR step, an **Onboarding Steps** list (Account Information, Payment Setup, Make a Payment and Renters Insurance can be added once per RMR step, so once added they turn gray, show a count and cannot be added again or moved into an RMR step that already has one; Form and File Upload can be added as many times as needed and keep their dark bar with a count; click a step, or drag it onto an RMR node, to add it: it goes to the bottom, or right after the selected step; the same list shows when one of its steps is selected), "Steps must be completed in order", and Connections.
- **Grouping (steps that are sent together).** The four RMR steps start in Group A (as in the mock). A step is only ever grouped with steps of its own type: Form steps cannot be grouped with Onboarding steps (each type's Group with list only offers its own type), and changing a step's type takes it out of its group. Under Connections, "Group with" is a plain multi-select with a checkbox per other RMR step: ticking a step joins it (and its group) to this step's group, unticking removes just that step, and a group left with one step dissolves. Grouped nodes share a **letter and a colour** (A blue, B orange, C green, D purple, E teal, F brown): a coloured left edge and a letter chip next to the RMR tag, instead of the mock's count chip. Hover a chip or the group summary to outline every member. This replaces the "4" chip in the Figma mock because a count has to be re-counted when a new RMR step is added; a letter does not.
- Click a Trigger node: the inspector shows a Settings dropdown of onboarding triggers (a lease is signed, onboarding is started / sent / completed, a step is completed, onboarding is overdue, an application is approved, a security deposit is paid, renters insurance is verified, move-in date is reached, a prospect becomes a tenant). Options read without "When" (the canvas adds it back); choosing one renames the trigger on the canvas and in every Connections list. The list of triggers is invented for this prototype (not from the design); confirm it with product.
- Click a Condition node: the inspector shows the condition's tests (field, is / is not, and a value that is a dropdown for yes/no, status and lease-type fields and free text for Unit and Property), "Add condition", "Remove condition", an "Any / All conditions are true" choice once there is more than one, and a plain-language summary. Editing a test rewrites the condition's title in the inspector, on the canvas and in the Connections lists (e.g. "If prospect has no pet"). The field list and value choices are invented for this prototype.
- Click a Notify node: Settings has "Who to notify" (Property manager, Leasing agent, Prospect, Maintenance team, Accounting; ticking people rewrites the node text, e.g. "Notify the PM and the leasing agent that onboarding was completed") a "Specific person" search (type a name, pick to add a removable chip; chosen people are added to the node text) and a Message field with a hamburger menu beside its title that fills in a message template; plus Connections. The recipients, the people list and the templates are invented for this prototype.
- Every inspector header uses the same layout (icon, type label, title, delete) on a white background; the icon and type label take the node type's colour and the bottom rule is the standard grey (Onboarding navy, Trigger green, Condition purple, Notify orange).
- A dark **action bar** (move up, move down, delete) floats above the right edge of whatever is selected, and follows zoom and scroll. **Steps** move up or down within their RMR step. **Nodes on the main line** (the first trigger, the RMR step, the closing trigger and Notify, i.e. the ones that are not part of a branch) trade places with their neighbour on the line; the branch (conditions and their RMR steps) stays where it is and connections are kept, so lines re-route. **Added nodes** reorder within their row. Items inside the branch and the ends of a list have greyed arrows. Delete removes the step or node.
- **Undo and Reset** (bottom of the left panel, and Cmd/Ctrl+Z) cover the whole workflow: adding, deleting and moving nodes and steps, step settings, connections, groups, trigger/condition/notify settings and renames. Undo steps back one change at a time and is greyed out at the start; Reset returns to the starting workflow and can itself be undone. Selecting things, zoom and panel layout are not changes. History lasts until you reload.
- Delete (trash) works on a selected step (it leaves its RMR step) and on any node (RMR, Trigger, Condition, Notify): its connections and group membership go with it, a group left with one member dissolves, and a "Step deleted" toast confirms. There is no undo yet.
- Step Library: click Trigger, RMR, Condition or Notify, or drag it onto the canvas, to add a new node. With a node (or one of its steps) selected, the new node goes in line directly after it, centred under it, and takes over that node's outgoing connections (so the chain stays joined: selected, then new, then what used to follow). With nothing selected it goes to the end of the main line, in line with the bottom steps (centred under the last step and connected to it), open their inspector straight away, and are connected with the Connections panel ("Connect to").
- Step Library search filters the library. The inspector is resizable (drag the divider; double-click resets).
- Connections list the selected Onboarding node's real connections in the chart (From, If for condition targets, To). The × removes that connection and its line; choosing a node in "Connect to" and pressing Connect draws a new one. The checklist's connection to "When onboarding is completed" is listed (To) but deliberately not drawn, to avoid the long loop line. Lines are straight where the nodes overlap; otherwise they run down, across and down with two rounded bends (lines merging into one node join just above it). Save shows a "Workflow saved" toast (nothing is stored).

- Dropdown menus in the right panel (Group with, Step Type, Connect to, people search, message templates) float over the page and always fit the screen: they open downward, or upward when there is more room above, size to their longest option and scroll if still too tall.

## Not real yet

- Action, Assign To and Wait in the step library (no node is designed for them), moving nodes around the canvas and the Health Findings tab.
- Nothing saves; step settings reset on reload. The Rent Manager field mapping for file requests is not shown, as in the template.
- The checklist has four steps (as in the Figma "Step edit" frame, which drops the duplicate Renters Insurance that the main frame still shows).

## Deliberate deviations

| Rule | Where | Why we kept it |
|---|---|---|
| Hex colours for step types | `assets/agents.css` (`--ag-*`) | The Figma design hard-codes trigger green, condition purple, notify orange, assign brown, wait teal and the pale node tints. Foundations has no tokens for them, so they are named once in this file. Ask Emma whether they should become tokens. |
| Icons not in RMX Iconography | `assets/icons-local.svg` | `call-split`, `how-to-reg`, `pause-circle`, `undo`, `home-work`, `drag-dots`, `onboarding-mark` were not found in the library; they use the glyph geometry exported from this Figma design. `bolt`, `lightbulb`, `campaign-outline`, `zoom-in`, `zoom-out`, `fit-screen`, `drag-indicator` come from RMX Iconography. |
| Custom canvas, palette, node and inspector layout | `assets/agents.css` | No RMX components exist for a workflow canvas. They are built from tokens and are not tagged as library components. |
| Unchecked checkbox tick | `assets/agents.css` | The foundation `rmx.css` draws the tick on unchecked boxes; hidden here until checked (the form-designer prototype patches this the same way). Worth raising with Emma. |
| Workflow badge weight | Agent head | The design uses Roboto Medium 12/20; Foundations has no such style, so the badge uses Label/S/SemiBold with a 20px line-height. |
| Tag corner radius 3px and 12.6px tracking | Step tags | Taken from the design (Web/Label/S/Medium); there is no 3px radius token. |
